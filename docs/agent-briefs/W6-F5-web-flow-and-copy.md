## Part A — findings (verify each first; a finding that is wrong → say so with evidence, don't change code)
For every confirmed finding: write a failing component test first, then fix, then the test passes. Name tests `F5-n …`.

1. `screens/reschedule/index.tsx` ~131: reschedule auto-selects a slot on open → "Move appointment" enabled before the
   user chose anything. Fix: start with **nothing selected**; the summary says "Pick a new time"; button disabled until a pick.
2. `screens/reschedule/index.tsx` ~155: success `navigate()` pushes; Back returns to a live form; the notice lives in
   history state and reappears. Fix: `navigate(…, { replace: true })`; clear the notice after it has been shown once.
3. `screens/book/BookForm.tsx` ~122: after 409 `SLOT_UNAVAILABLE`, `setSlot(null)` re-triggers auto-select and Confirm
   is enabled for a time the user never chose. Fix: after a 409 keep the selection empty until the user picks a slot or
   an alternative (auto-select stays only for vehicle / service / dealer / date changes, SPEC §8).
4. `screens/reschedule/index.tsx` ~322: PARTS_UNAVAILABLE panel says "Try another dealership" on a screen where the
   dealership is fixed. Fix: reschedule wording "Try a later date."
5. Clock: record / list / Today chip use the browser clock while MSW `?mock=` scenarios use a pinned clock. Fix for mock
   mode: one `businessNow()` helper in `src/lib/` used everywhere "now" matters (record actions, list tabs, Today chip),
   returning the scenario clock under MSW and `Date.now()` otherwise. Real-API mode with `CLOCK_OVERRIDE` stays as
   documented (no API change) — note it in the report.
6. `screens/book/BookForm.tsx` ~65: `services[0]!` undefined when no service fits the vehicle → render crash, blank app.
   Fix: friendly empty state ("No services are available for this vehicle. Choose another vehicle."), plus an app-level
   error boundary (`App.tsx`) with a plain message and a "Go back to booking" link.
7. `screens/book/Confirmation.tsx` ~83: always "We'll remind you the day before", also for same-day. Fix: same-day →
   show the late-release rule instead (minutes from `lateGraceMin`).
8. `screens/board/index.tsx` ~254: check-in banner shows raw `LATE_ARRIVAL` in error styling. Fix: plain outcome
   sentences per result (checked in; released because more than N min late — styled as an informational outcome, not a
   failure; not active → "This booking can't be checked in (it was cancelled or already checked in)").
9. `screens/record/index.tsx` ~166: late-release warning and "Add to calendar" show for checked-in / past appointments.
   Fix: only for upcoming, not-checked-in appointments.
10. Duplication: reschedule copies ~120 lines of Book's time-picker. Fix: extract `<TimePicker>` in `screens/book/`
    (date strip, legend, slot grid, conflict panel, same-day notice, blocked panels, loading/error) with props for
    `currentStart` and the fixed-dealership wording; use it from both forms. Book's behaviour and tests stay green.

## Part B — plain-language pass (every user-facing string)
Principles: short sentences (≤ 15 words where possible), everyday words, say what happened + what to do next, no codes
or jargon on screen (`SLOT_UNAVAILABLE`, `APT-…` as a label is fine as a reference number, but explain it once:
"Booking number"), consistent names for the same thing across screens, buttons start with a verb, errors never blame the
user. Keep "service bay" / "technician" but add a one-line explanation where they first appear (e.g. "A bay is the
space where your car is worked on"). Check status labels, empty states, loading and error states, dialogs, aria-labels.

**SPEC §8 quotes some strings verbatim** (same-day notice, the three blocked panels, slot labels, "Checking bay and
technician…"). Do **not** change those — list your proposed simpler wording for each in the report; Opus updates SPEC
and you (or a follow-up) apply them. Everything else you may change.

Deliver a table in the report: screen · before · after · why, for every changed string.
